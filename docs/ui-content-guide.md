# la vie：界面与文案规范

## 品牌命名

产品名使用「la vie」，说明文字使用「两个人的生活空间」。

- 名称和说明不使用「赏金」「佣金」「交易」「接单大厅」等词，避免把私密空间表达成公开市场。
- 导航、页面标题和按钮优先说用户要做的事，不重复堆叠产品名。

## 信息层级

任务列表按以下顺序展示：

1. 分类与当前状态
2. 约定回报
3. 任务标题与简短说明
4. 地点
5. 发布者与截止时间

任务详情在操作前集中展示回报、地点和完成时间，减少参与者在不同区块寻找关键信息。

## 统一用词

| 系统状态 | 用户界面 |
| --- | --- |
| `PUBLISHED` | 待领取 |
| `CLAIMED` | 已分配 |
| `IN_PROGRESS` | 进行中 |
| `SUBMITTED` | 等待验收 |
| `REVISION_REQUESTED` | 需要修改 |
| `COMPLETED` | 已完成 |
| `DISPUTED` | 争议处理中 |
| `PENDING`（申请） | 等待处理 |
| `ACCEPTED`（申请） | 申请已通过 |
| `REJECTED`（申请） | 申请未通过 |

- 对用户使用「回报」，数据库和代码仍可保留 `reward`。
- 使用「空间」「清单」「手帐」「日历」，不使用偏运营化的「大厅」「广场」或偏交易化的「接单市场」。
- 使用「我的工作」「我创建的」「分配给我的」，强调内部协作关系。
- 使用「确认完成」「退回修改」，让按钮明确说明结果。

事项必须归属于 la vie 空间，项目外用户无法查询。界面不要求创建者选择可见范围、加入方式或参与人数；地点、完成标准和补充说明均使用单一文本字段表达。

手帐和点评统一称为「记录」：记录日期是日历上的主索引，Markdown 只作为迁移输入格式，在线编辑后的正文和版本以数据库为准。

项目角色统一使用「负责人、管理员、成员、只读成员」。权限判断始终以任务所属项目的成员记录为准，不能使用全局用户身份代替项目权限。

## 文案检查

- 不承诺平台没有实现的担保、支付、信用或撮合效果。
- 不使用虚假的任务数、参与人数、成交额和成功率。
- 危险操作说明影响范围；空状态说明原因和下一步。
- 表单标签说明实际选择结果，示例不包含敏感个人信息。
- 资金、物品和线下服务统一提示：平台只记录约定，不代收代付，双方自行履约并留存凭证。

## 开源产品参考

- [Superteam Earn](https://github.com/SuperteamDAO/earn)：参考任务价值、技能、截止时间和参与动作的优先级。
- [Plane](https://github.com/makeplane/plane)：参考工作台的信息密度、状态和筛选组织。
- [Gitpay](https://github.com/worknenjoy/gitpay)：参考发布者、参与者、提交和验收的角色表达。
- [Opire](https://github.com/opire)：参考对回报规则的直接、透明表达。
- [Octasol](https://github.com/Octasol/octasol)：参考 Next.js、Tailwind 与任务市场的开源实现边界。

以上只作为信息架构和表达方式参考，视觉、名称与文案均为本项目重新设计。
